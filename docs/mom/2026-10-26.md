
# RAG 기반 AI 학습 서비스 — MVP API 명세 v1.0

## 1. 개요

### 기능적 요구사항

1. 사용자 관리: 회원가입, 로그인, 로그아웃, 사용자 정보 조회
2. 자료 관리: URL 기반 자료 등록, 조회, 삭제 (향후 PDF, PPT, 이미지, 음성, 영상으로 확장)
3. 일반 대화: 사용자별 단일 대화 기록 유지 및 AI 응답 생성
4. 자료 검색: 등록된 자료에 대한 검색 및 RAG 기반 답변 생성

### 시스템 구성

| 구성 요소 | 역할                                       |
| --------- | ------------------------------------------ |
| Frontend  | 사용자 인터페이스 및 API 호출              |
| Backend   | 인증, 사용자·자료·대화 관리              |
| AI (RAG)  | 콘텐츠 추출, 청킹, 임베딩, 검색, 답변 생성 |

### 설계 원칙

- REST API 및 JSON 기반 통신
- 사용자는 하나의 연속된 대화 기록만 보유하며 `Conversation` 도메인은 사용하지 않음
- 인증은 서버 세션과 HttpOnly 쿠키 기반으로 가정
- 자료 등록 및 AI 색인은 비동기 처리
- Backend가 서비스 데이터, AI 서버가 RAG 검색 데이터 관리
- 모든 사용자 자료는 소유권 검증 후 접근
- API 버전은 `v1` 사용

## 2. Frontend ↔ Backend API

### 2.1. 사용자 및 인증

| HTTP Method | URL                     | 설명                            |
| ----------- | ----------------------- | ------------------------------- |
| POST        | `/api/v1/auth/signup` | 신규 사용자 회원가입            |
| POST        | `/api/v1/auth/login`  | 사용자 인증 및 로그인 세션 생성 |
| POST        | `/api/v1/auth/logout` | 로그아웃 및 인증 세션 무효화    |
| GET         | `/api/v1/users/me`    | 현재 로그인한 사용자 정보 조회  |

### 2.2. 자료 관리

| HTTP Method | URL                                | 설명                                        |
| ----------- | ---------------------------------- | ------------------------------------------- |
| POST        | `/api/v1/resources`              | URL 기반 신규 자료 등록 및 처리 작업 시작   |
| GET         | `/api/v1/resources`              | 현재 사용자가 등록한 자료 목록 조회         |
| GET         | `/api/v1/resources/{resourceId}` | 특정 자료의 상세 정보 및 처리 상태 조회     |
| DELETE      | `/api/v1/resources/{resourceId}` | 자료 삭제 및 관련 RAG 검색 데이터 삭제 요청 |

### 2.3. 대화 관리

| HTTP Method | URL                  | 설명                                |
| ----------- | -------------------- | ----------------------------------- |
| GET         | `/api/v1/messages` | 현재 사용자의 대화 기록 조회        |
| POST        | `/api/v1/messages` | 사용자 메시지 전송 및 AI 답변 생성  |
| DELETE      | `/api/v1/messages` | 현재 사용자의 전체 대화 기록 초기화 |

### 2.4. 자료 검색

| HTTP Method | URL                | 설명                                         |
| ----------- | ------------------ | -------------------------------------------- |
| POST        | `/api/v1/search` | 현재 사용자가 등록한 자료에서 관련 내용 검색 |

## 3. Backend ↔ AI(RAG) API

### 3.1. 자료 수집 및 색인

| HTTP Method | URL                                     | 설명                                             |
| ----------- | --------------------------------------- | ------------------------------------------------ |
| POST        | `/internal/v1/ingestions`             | 자료 콘텐츠 추출, 청킹, 임베딩 및 색인 작업 요청 |
| GET         | `/internal/v1/ingestions/{jobId}`     | 자료 처리 작업의 진행 상태 및 결과 조회          |
| DELETE      | `/internal/v1/resources/{resourceId}` | 해당 자료의 청크 및 임베딩 데이터 삭제           |

### 3.2. 검색 및 답변 생성

| HTTP Method | URL                               | 설명                                      |
| ----------- | --------------------------------- | ----------------------------------------- |
| POST        | `/internal/v1/retrieval/search` | 사용자에게 허용된 자료에서 관련 청크 검색 |
| POST        | `/internal/v1/answers`          | 일반 대화 또는 RAG 기반 AI 답변 생성      |

## 4. 공통 데이터 모델

### 4.1. User

| 필드         | 타입     | 설명                           |
| ------------ | -------- | ------------------------------ |
| id           | UUID     | 사용자 식별자                  |
| email        | String   | 이메일                         |
| passwordHash | String   | 비밀번호 해시 (서버 내부 전용) |
| createdAt    | DateTime | 가입 일시                      |

### 4.2. Resource

| 필드      | 타입           | 설명                    |
| --------- | -------------- | ----------------------- |
| id        | UUID           | 자료 식별자             |
| userId    | UUID           | 자료 소유자             |
| title     | String?        | 자료 제목               |
| type      | ResourceType   | 자료 유형               |
| source    | Object         | 원본 URL 또는 파일 참조 |
| status    | ResourceStatus | 자료 처리 상태          |
| createdAt | DateTime       | 등록 일시               |
| updatedAt | DateTime       | 수정 일시               |

`ResourceType`:

```
URL
PDF
PPT
IMAGE
AUDIO
VIDEO
```

MVP에서 지원하는 유형은 `URL`만으로 제한한다.

`ResourceStatus`:

```
REGISTERED
EXTRACTING
INDEXING
READY
FAILED
DELETED
```

### 4.3. IngestionJob

| 필드         | 타입      | 설명           |
| ------------ | --------- | -------------- |
| id           | UUID      | 작업 식별자    |
| resourceId   | UUID      | 처리 대상 자료 |
| status       | JobStatus | 작업 진행 상태 |
| errorMessage | String?   | 처리 실패 사유 |
| startedAt    | DateTime? | 작업 시작 일시 |
| completedAt  | DateTime? | 작업 완료 일시 |

### 4.4. Message

| 필드      | 타입             | 설명                  |
| --------- | ---------------- | --------------------- |
| id        | UUID             | 메시지 식별자         |
| userId    | UUID             | 메시지 소유자         |
| role      | MessageRole      | USER 또는 ASSISTANT   |
| content   | String           | 메시지 내용           |
| mode      | ConversationMode | GENERAL 또는 RESOURCE |
| createdAt | DateTime         | 메시지 생성 일시      |

`ConversationMode`:

- `GENERAL`: 자료 검색 없는 일반적인 AI 대화
- `RESOURCE`: 등록 자료 검색을 기반으로 답변하는 대화

| 필드          | 타입    | 설명           |
| ------------- | ------- | -------------- |

| embedding     | Vector  | 임베딩 벡터    |
| sequence      | Integer | 문서 내 순서   |
| sourceLocator | Object  | 원문 위치 정보 |

### 4.6. Citation

| 필드       | 타입   | 설명                |

## 5. 주요 처리 흐름

### 자료 등록

```
Frontend
   │
   │ POST /api/v1/resources
   ▼
Backend
   │
   ├── Resource 생성
   ├── IngestionJob 생성
   │
   │ POST /internal/v1/ingestions
   ▼
AI Server
   │
   ├── 원본 콘텐츠 추출
   ├── 청킹
   ├── 임베딩 생성
   └── 벡터 데이터 저장
   │
   ▼
Backend
   │
   └── 작업 상태 조회 후 Resource 상태 갱신
```

### 일반 대화 및 RAG 대화

```
Frontend
   │
   │ POST /api/v1/messages
   ▼
Backend
   │
   ├── 사용자 인증
   ├── 사용자 메시지 저장
   └── 대화 기록 및 허용 자료 조회
   │
   │ POST /internal/v1/answers
   ▼
AI Server
   │
   ├── GENERAL: LLM 답변 생성
   │
   └── RESOURCE:
       ├── 질문 임베딩
       ├── 관련 청크 검색
       └── 근거 기반 LLM 답변 생성
   │
   ▼
Backend
   │
   ├── AI 답변 및 출처 검증·조합
   └── AI 메시지 저장
   │
   ▼
Frontend
```

### 자료 삭제

```
Frontend
   │
   │ DELETE /api/v1/resources/{resourceId}
   ▼
Backend
   │
   ├── 자료 소유권 검증
   ├── 자료 검색 제외 처리
   │
   │ DELETE /internal/v1/resources/{resourceId}
   ▼
AI Server
   │
   └── 해당 자료의 Chunk 및 Embedding 삭제
   │
   ▼
Backend
   │
   └── 삭제 결과 반영
```

자료 삭제는 Backend와 AI 서버에 걸친 작업이므로 부분 실패 시 재시도를 고려한다. 삭제 요청 이후 해당 자료가 검색되지 않도록 처리해야 한다.

## 6. 공통 API 규칙

| 항목           | 규칙                                     |
| -------------- | ---------------------------------------- |
| 데이터 형식    | `application/json`                     |
| 인증           | 서버 세션 + HttpOnly 쿠키                |
| 날짜           | ISO 8601 (UTC 권장)                      |
| 식별자         | UUID                                     |
| 페이지네이션   | `limit`, `cursor`                    |
| 오류 응답      | 통일된 `error.code`, `error.message` |
| 내부 API       | 외부에 노출하지 않고 서비스 간 인증 적용 |
| 비동기 작업    | 작업 ID 발급 후 상태 조회                |
| 자료 검색 범위 | 현재 사용자가 접근 가능한 READY 자료만   |
| 삭제           | 반복 호출에 안전하도록 멱등성 고려       |

### 공통 오류 코드

| 코드                       | HTTP 상태 | 설명                 |
| -------------------------- | --------- | -------------------- |
| `INVALID_REQUEST`        | 400       | 잘못된 요청          |
| `UNAUTHORIZED`           | 401       | 인증되지 않은 사용자 |
| `FORBIDDEN`              | 403       | 접근 권한 없음       |
| `RESOURCE_NOT_FOUND`     | 404       | 자료를 찾을 수 없음  |
| `RESOURCE_NOT_READY`     | 409       | 자료 처리 미완료     |
| `AI_SERVICE_UNAVAILABLE` | 503       | AI 서버 사용 불가    |

자료 처리 중 발생한 콘텐츠 접근 실패나 추출 실패는 비동기 작업의 `FAILED` 상태와 오류 정보로 관리한다.
