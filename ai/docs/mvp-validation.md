# 찾 AI MVP 검증 계획

2026-10-29 · 구현 전 검증 계획

## 목표

공개 노션 자료를 빠르게 수집·임베딩하고, 사용자의 질문에 관련 근거와 정확한 출처를 포함한 유용한 답변을 제공할 수 있는지 확인한다. 자료 용도는 학습으로 한정하지 않는다. 운영 복구·자동 재시도·대규모 부하 검증은 이번 평가 범위에서 제외한다.

## 평가 자료와 질문

서로 다른 구조와 주제의 공개 노션 페이지를 선정한다. 초기에는 소수의 고정 자료로 시작하고 평가 URL, 확인 날짜, 원문 근거 발췌를 함께 기록한다. 문서 예시 URL은 실제 평가 자료가 아니며 접근 가능한 URL로 교체한다.

| 자료 구성 | 확인할 사항 |
| --- | --- |
| 제목·본문·목록 중심 문서 | 본문 순서와 핵심 내용 수집 |
| 표·토글·중첩 구조 문서 | 내용 누락, 구조 손실, 추출 지원 범위 |
| 짧은 문서와 긴 문서 | 빈 문서 오판, 청크 경계와 문맥 보존 |
| 여러 주제의 문서 | 자료 선택, 무관한 근거 혼입 여부 |

각 자료에 직접 답할 수 있는 질문, 여러 문단을 종합해야 하는 질문, 표현을 바꾼 질문, 자료에 답이 없는 질문을 준비한다. 질문별로 기대 답변 요점과 근거 절·발췌를 사람이 먼저 작성한다. 업무 안내·제품 설명·기술 참고 자료 등 여러 용도를 포함한다.

## 실행과 기록

1. 평가 자료를 등록하고 원문과 추출한 `Document`를 비교한다.
2. 청크 크기·중첩, 분할 방식, 임베딩 모델, 검색 `topK`, 답변 모델·프롬프트 버전을 기록한다.
3. 검색 API로 기대 근거가 상위 결과에 포함되는지 확인한다.
4. 같은 질문으로 답변을 생성하고 정확성·유용성·출처 일치를 확인한다.
5. 같은 평가 세트에서 한 번에 한 설정을 바꾸어 결과를 비교한다. 원문이 바뀌었다면 변경 사실을 기록하고 비교 조건을 맞춘다.

| 단계 | 기록할 결과 |
| --- | --- |
| 수집 | 성공 여부, 빠진 본문·표·토글, 메뉴 등 불필요한 텍스트 |
| 청킹 | 생성 청크 수, 근거 문맥의 단절, 절·원문 메타데이터 보존 |
| 검색 | 상위 K개 안의 기대 근거 포함 여부(질문별 성공/실패 및 전체 비율) |
| 답변 | 요점 충족, 근거 없는 주장, 자료 간 혼동, 이해하기 쉬운 설명 |
| 출처 | 인용 청크·발췌·원문 URL의 일치 및 실제 답변 주장 뒷받침 여부 |
| 근거 부족 | 자료에 없는 질문에 `INSUFFICIENT_EVIDENCE`를 반환하는지 |
| 시간 | 접수부터 색인 완료까지의 시간, 수집·임베딩·검색·생성 단계별 시간, 질문부터 답변까지의 시간 |

처리 시간은 평가 실행에서 직접 기록한다. 운영 모니터링 시스템 구축을 요구하지 않는다. 평가는 성공 사례뿐 아니라 실패·시간 초과도 포함하고, 모델 호출 비용을 확인할 수 있다면 함께 기록한다.

## 기본 동작 확인

- 비공개·삭제·미지원 URL과 로딩 실패가 정상 자료로 색인되지 않는지 확인한다.
- 다른 사용자 자료, 색인 미완료 자료, 삭제 자료가 검색·답변에 포함되지 않는지 확인한다.
- 접수 후 조회로 성공·실패를 확인하고, 실패를 숨기거나 자동 재시도하지 않는지 확인한다.
- 프로세스를 재시작하면 이전 작업 조회는 `404 JOB_NOT_FOUND`가 되고 호출자가 폴링을 중단하는지 확인한다. 완료된 DB 자료는 계속 검색 가능해야 한다.

## 판단과 후속 작업

첫 실행으로 품질과 시간의 기준선을 만든 뒤, 기대 근거 검색 비율·답변 평가·허용 지연의 합격 기준을 정한다. 아직 측정하지 않은 수치나 합격 여부를 확정하지 않는다. 사용자 간 자료 혼입과 잘못된 출처는 우선 수정한다.

수집 누락은 로더, 근거 미검색은 청킹·임베딩·검색 설정, 근거는 있지만 답변이 부정확한 경우는 문맥 구성·프롬프트를 우선 점검한다. 실패 단계별로 개선 결과를 비교한 뒤 일반 웹·파일 지원과 운영 설계의 우선순위를 결정한다.
