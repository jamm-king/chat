# AI 기능 검증 계획

2026-11-03 · [Backend–AI 계약](architecture/backend-ai-contract.md) 기준

## 현재 검증과 후속 검증 구분

현재 구현은 OAuth, 연결별 페이지 검색·미리보기, 공통 자료 ID의 COLLECT 비동기 수집·저장·참조 선택 등록이다. 자료 삭제·진행 작업 취소도 구현돼 있다. 청킹·임베딩·색인도 구현됐고 설정 활성화가 필요하다. RAG 검색·답변은 목표 계약이며 구현 전 성공 판정을 하지 않는다. 자동 테스트는 Notion 모의 응답·SQLite를 사용하므로 실제 Notion·PostgreSQL 확인과 구분한다.

## 1. OAuth·페이지 선택

- Backend 로그인 사용자에서 userId를 결정하고 AI 서비스 토큰을 Frontend에 노출하지 않는다.
- 시작 응답의 Set-Cookie와 콜백 요청의 OAuth 쿠키만 올바르게 중계한다. 사용자 로그인 쿠키는 AI로 전달하지 않는다.
- 같은 브라우저·콜백 호스트에서 승인·취소·만료·중복 콜백·다른 사용자 연결을 확인한다.
- 여러 계정·워크스페이스 연결을 구분한다. 재인증은 사용자·workspace·bot 키로 갱신된다.
- 페이지 검색의 커서·제목 검색을 확인한다. Search 결과를 전체 접근 가능 문서 목록이라고 보장하지 않는다.
- 연결에 공유한 비공개 페이지는 수집할 수 있고, 미공유 페이지는 실패해야 한다. 비공개라는 이유만으로 미지원 처리하지 않는다.

## 2. 수집·참조·저장

문단·목록·표·토글·긴 문서·빈 페이지와 page/database/video 참조가 있는 소수의 고정 자료를 사용한다. 평가 자료는 connectionId·pageId·확인 날짜와 원문 근거를 기록하되 토큰은 기록하지 않는다.

- 원본 Markdown·본문·제목·출처·수정 시각·수집 시각이 보존되는지 확인한다.
- 본문과 참조를 구분한다. 참조만 존재할 때 content_status가 complete를 유지하는지 확인한다.
- 실제 잘림·unknown 블록은 partial로 기록한다. 미지원 콘텐츠를 조용히 완전 수집으로 처리하지 않는다.
- 부모 등록만으로 참조 페이지·DB 행에 추가 수집 요청이 나가지 않는지 확인한다.
- 사용자가 선택한 페이지 참조만 하위 자료로 등록하고 소유권·같은 연결·현재 접근 권한을 검증한다.
- 자식 실패 후 부모의 본문·상태가 유지되는지 확인한다. 중복 등록·참조가 아닌 대상 등록도 확인한다.

## 3. 공통 ID·비동기 계약 — 현재 검증 대상

- Backend resourceId가 AI 저장·조회·출처·삭제에서도 동일한지 확인한다.
- 본문 조회를 지연시켜도 접수는 202/QUEUED로 먼저 반환하는지 확인한다.
- 같은 jobId·입력 재접수는 재실행하지 않고 다른 입력은 충돌하는지 확인한다.
- COLLECT 완료는 작업 SUCCEEDED, 자료 COLLECTED, ready=false이며 폴링이 끝나는지 확인한다.
- EXTRACTED는 중간 상태이며 종료 판정으로 사용하지 않는지 확인한다.
- 색인 설정 비활성 시 COLLECT_AND_INDEX를 명시적으로 거절하는지 확인한다.
- 프로세스 재시작 후 이전 작업은 404 JOB_NOT_FOUND로 폴링을 끝내고 자동 재접수하지 않는지 확인한다. 저장된 자료·연결은 유지해야 한다.
- 부분 본문은 보존할 수 있으나 색인에서는 CONTENT_INCOMPLETE로 실패해야 한다.

## 4. 검색·답변 — 구현 후 검증 / 삭제 — 현재 검증 대상

색인·삭제는 현재 검증 대상이며, RAG 검색·답변은 미구현이므로 후속 평가다. 모의 임베딩과 실제 공급자 호출·pgvector 검증은 구분한다.

| 항목 | 확인 방법 |
| --- | --- |
| 색인 | 청크 설정·모델·수·시간 기록, 완성된 색인만 READY |
| 검색 | 직접 질문·표현 변경·종합 질문별 기대 근거가 topK에 있는지 |
| 답변 | 근거 없는 주장·자료 혼동·요점 충족·출처 일치 |
| 근거 부족 | 자료에 없는 질문에 INSUFFICIENT_EVIDENCE |
| 범위 | 다른 사용자·COLLECTED·삭제·색인 미완료 자료 제외 |
| 삭제 | 즉시 검색 제외, AI 원본·본문·참조·벡터 삭제, 실패 시 제외 유지 |
| 출처 보존 | 현재 자료 삭제 후에도 Backend 답변·출처 스냅샷 확인 |
| 계층 | 부모 삭제는 자식 자동 삭제를 유발하지 않음 |

색인 설정을 바꿀 때 같은 질문 세트로 비교하고 청크·모델·프롬프트 버전을 기록한다. 실제 본문이 바뀌면 비교 조건을 구분한다. 검색 지연·작업 시간은 실행에서 측정하며 운영 모니터링 구축은 요구하지 않는다.

## 판단

첫 실행으로 품질·시간 기준선을 만든 후 합격 기준을 정한다. 아직 측정하지 않은 성능·합격률을 확정하지 않는다. 사용자 자료 혼입·잘못된 출처를 우선 수정한다. 자동 복구·재시도·대규모 부하 검증은 이후 범위다.
