# 찾 — 자료 로더 설계

2026-10-29 · 구현 전 설계

로더의 추상화, 수집 방식 선택과 공통 문서 변환은 AI 하위 프로젝트가 담당한다. Backend는 자료 소유권 검증과 수집 작업 접수·상태 관리를 담당하며, AI 내부 로더를 직접 선택하거나 호출하지 않는다.

## 서비스 범위와 MVP

찾은 웹페이지와 파일(PPT, Word, TXT, PDF 등)의 내용을 수집하고 검색·근거 기반 답변에 활용하는 서비스다. 자료의 목적은 학습으로 제한하지 않는다.

MVP는 사용자가 공개 노션 페이지 URL 한 개를 등록하면 해당 페이지를 수집하고 청킹·임베딩하여 검색 가능한 자료로 만드는 흐름을 구현한다. 일반 웹페이지 수집, 파일 입력, 하위 페이지 일괄 수집은 이후 확장한다. 공개 페이지라도 접근 실패나 본문 추출 실패가 발생할 수 있으며 모든 노션 URL의 수집 성공을 보장하지 않는다.

## 로더 구조

```text
자료 등록 → 입력 종류에 따라 로더 선택
  ├─ 웹 로더: URL → 페이지 수집 → 사이트에 맞는 본문 추출
  │   └─ MVP: 공개 노션 페이지
  └─ 파일 로더: 파일 참조 → 형식별 본문 추출(이후 구현)
      ↓
공통 문서 → 청킹 → 임베딩 → 색인 → READY
```

- 웹 로더는 URL 접근, 필요 시 브라우저 렌더링, 본문·문서 구조·출처 추출을 담당한다. MVP에는 노션에 맞는 추출 처리를 구현하되 수집과 사이트별 추출을 분리하여 다른 웹사이트로 확장할 수 있게 한다.
- 파일 로더는 향후 파일 참조를 받아 PPT·Word·TXT 등 형식별 파서로 내용을 추출한다. MVP에서는 인터페이스 경계만 정의하고 파일 업로드 API나 파서를 구현하지 않는다.
- 청킹·임베딩은 로더 외부의 공통 파이프라인이 담당한다. 로더는 벡터 데이터를 생성하거나 대화를 저장하지 않는다.
- 기존 `source.type: URL`을 유지한다. 노션은 웹 로더의 수집 대상이며 별도 자료 유형이 아니다. 향후 파일 입력 계약은 파일 저장·소유권·형식 검증 정책과 함께 별도로 정의한다.

## 공통 문서 출력

다음은 로더와 청킹 단계 사이의 내부 개념 모델이다. Backend ↔ AI API의 추가 요청·응답 필드를 의미하지 않는다.

| 항목 | 내용 |
| --- | --- |
| 제목 | 원문 제목. 추출할 수 없으면 null |
| 원본 참조 | 입력 URL과 최종 원문 URL. 파일 로더에서는 파일 식별자 |
| 수집 시각 | 이번 수집이 완료된 UTC 시각 |
| 본문 요소 | 순서가 있는 제목·문단·목록·표 등의 텍스트와 구조 |
| 위치 정보 | 본문 요소에 대응하는 절 제목, 확보 가능한 원문 앵커 등. 파일에서는 슬라이드 번호 등으로 확장 |

청킹 시 본문 요소의 순서와 출처 정보를 전달한다. MVP의 외부 출처 응답은 기존 `locator: {type: URL, url, section}`을 유지하며 정밀한 블록 이동을 보장하지 않는다. 웹 스크래핑 과정에서 노션 블록 ID를 항상 얻을 수 있다고 가정하지 않는다.

## MVP 노션 수집 정책

- 로그인 없이 열람 가능한 `notion.site`, `notion.so` 및 각 하위 도메인의 노션 페이지를 대상으로 한다. 사용자 지정 도메인은 이후 확장한다.
- 사용자는 URL만 입력한다. 노션 OAuth 연결, 공식 API 토큰, 사용자의 로그인 쿠키는 요구하지 않는다. 비공개 자료 연결은 별도 기능으로 검토한다.
- HTML 직접 추출을 우선하고, 필요한 경우 브라우저 렌더링 후 본문을 추출한다. 구체적인 추출 방법과 본문 준비 판정은 실제 공개 노션 페이지로 검증한다.
- 입력 페이지 본문만 수집한다. 표·토글 등의 추출 가능 범위를 검증하고, 하위 페이지·첨부파일·외부 임베드 본문과 이미지 OCR은 제외한다.
- 최초 URL뿐 아니라 리다이렉트, 브라우저 이동, 렌더링 하위 요청에도 공개 주소 검사를 적용한다. 본문 렌더링을 위한 하위 요청 허용과 링크를 따라 다른 문서를 수집하는 동작은 구분한다.
- 로그인·접근 제한·로딩 화면만 얻은 경우 색인하지 않는다. 구체적인 실패 코드와 한도는 [AI 서비스 정책](../api/references.md)의 수집 표와 오류 정책을 따른다.
- 자동 동기화는 MVP 범위에 포함하지 않는다. 수집 시점의 내용을 색인하며 원문 변경 후 다시 수집하려면 기존 정책에 따라 새 자료 ID로 등록한다.

## 구현 전에 검증·확정할 항목

공개 노션 페이지를 대상으로 HTML 직접 추출과 브라우저 렌더링을 비교하고 제목·본문·목록·표·중첩 토글의 추출 결과를 확인한다. 로그인 필요, 삭제, 미지원 URL, 본문 없는 페이지, 렌더링 시간 초과도 확인한다.

브라우저 렌더링의 본문 준비 조건, 시도별 기한, 총 전송량·요청 수·메모리 한도를 검증 결과에 따라 확정하고 AI 서비스 정책과 OpenAPI 설명에 함께 반영한다. 이 문서는 구현·지원 검증이 완료되었다는 의미가 아니다.
